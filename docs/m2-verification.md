# M2 真机验收清单

M2 实现覆盖向量索引、混合/跨书检索与长期记忆。自动化测试与 Android bundle 只能验证静态逻辑；端点兼容性、性能和杀进程续跑仍需在 Android dev build 真机完成。

## 0. 前置条件

- [ ] 先完成 `docs/m1-verification.md` 的 M0-B/M1 回归
- [ ] 使用 Expo dev build，不使用 Expo Go
- [ ] 准备一个 OpenAI 兼容 Chat 端点和一个 Embedding 端点
- [ ] Embedding 端点返回 1024 维；若模型默认维度不同，在设置中填 `dimensions=1024`
- [ ] 准备一本约 30 万字的中文书，以及至少两本内容有关联的书

## 1. 向量配置与全局 embed_sig

- [ ] 设置页填写向量 Base URL、API Key、Model，测试连接成功后保存
- [ ] 非 1024 维响应被拒绝，并提示更换模型或填写 `dimensions=1024`
- [ ] Base URL、Model 或 dimensions 改变后提示全库重建
- [ ] 只修改 Rerank Model 不触发重建
- [ ] 选择“稍后”时关键词检索仍可用，不使用新配置下未完成的向量
- [ ] 选择“立即重建”后逐本显示书名、总数和分块进度
- [ ] 每本书新向量全部成功后，书级 centroid 写入、active `embed_sig` 切换和旧向量清理同时生效；任何一步失败都保留旧 active sig
- [ ] 重建过程中再次修改向量配置：旧任务在下一批或最终提交前停止，不会覆盖新配置状态
- [ ] 同一本书快速重复点击重建，第二个任务被拒绝，不出现两组请求并发写入

## 2. 索引状态机与性能

- [ ] 书籍详情从“关键词模式/可检索”进入“向量化中”，最终显示“向量已就绪”
- [ ] 点击“暂停索引”后状态为“部分完成”，再次点击从已有分块继续
- [ ] 向量化中强制结束 App；重开后任务自动续跑，而不是从第 0 块开始
- [ ] 断网或端点 429/超时后状态为“部分完成”，恢复网络后可继续
- [ ] 未配置向量端点时保持关键词模式，阅读、划线和关键词搜索正常
- [ ] 使用固定设备、Android/build 类型、书籍 SHA-256/字符数/chunk 数、端点/模型与网络，重复至少 3 次记录索引耗时、请求批次和峰值内存
- [ ] 30 万字书在上述固定条件下验证目标约 1～2 分钟；条件未记录时不判定该目标

## 3. 单书混合检索

- [ ] 向量就绪后提一个跨章节、关键词不完全重合的问题
- [ ] 回答引用来自正确章节，点击 `[Cn]` 和引用卡片都能跳到准确原文
- [ ] 飞行模式下 AI 明确失败，但阅读、划线与关键词搜索仍可用
- [ ] 改向量配置但尚未重建时，旧模型向量不会被新模型查询向量误用

## 4. 书库会话与两阶段检索

- [ ] 书架出现“书库问答”，进入后顶部显示“整个书库”
- [ ] 提问比较两本书的共同主题，回答包含多本书的正确书名与引用
- [ ] 引用卡片显示书名；点击后进入对应书籍和章节/位置
- [ ] 只有部分书完成当前向量配置时，未完成书仍可走关键词召回，但不使用半成品向量
- [ ] 没有任何关键词命中时，仍能通过书级向量路由召回语义相关书籍和原文
- [ ] 记录无关键词查询的书库规模、候选书数、延迟 p50/p95 与峰值内存，界面无明显卡顿
- [ ] 与查询点积为 0 或负数的纯向量块不会占据最终 Top-K

## 5. 长期记忆

- [ ] 连续 6 轮表达稳定偏好/背景/兴趣后退出会话，设置页“AI 对你的了解”出现相关记忆
- [ ] 记忆不包含书中情节、原文或模型自行推断的敏感信息
- [ ] 新会话中的回答遵循已记录偏好（例如“回答简洁/分点”）
- [ ] 重复或更新同一偏好不会无限新增重复项
- [ ] 设置页逐条删除后，该记忆立即消失且后续对话不再注入

## 6. 隐私与端点安全

- [ ] `http://` Base URL 无法保存或测试，界面说明必须使用 HTTPS
- [ ] onboarding 和设置页明确说明：Chat 会发送对话/记忆/相关原文，Embedding 会发送书籍分块和查询，Rerank 会发送候选片段
- [ ] API Key 只持久化于 SecureStore，SQLite 只有掩码；诊断、错误提示、测试报告和 `adb logcat` 不出现 Key、Authorization 或完整原文
- [ ] Rerank 端点不兼容或离线时自动回退原排序，不影响基本检索

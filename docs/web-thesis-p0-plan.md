# P0：实验基线与开题演示底线

日期：2026-10-28。状态：待用户确认实施；本文件仅为方案，未执行下述代码改动、在线模型实验或浏览器验收。

关联：[总方案](web-thesis-plan.md)、[共享接口与协作约定SC-1.1](web-thesis-shared-contracts.md)、[改造前只读检查记录](web-thesis-baseline-check.md)。

共享约定是P1a及以后分阶段落地的目标接口；P0仍采集当前接口的基线，不提前把请求结构、SSE或记忆数据换成新版。后续 [RAG实施方案](web-thesis-rag-plan.md) 和 [记忆实施方案](web-thesis-memory-plan.md) 不改变P0范围。

## 1. 为什么现在做P0

已确认2026-11-07开题答辩，其他主要里程碑在2027年，具体日期未定。开题前不必完成全部改造，应优先证明：问题真实、原型已有、技术路线可落地、最终效果有评价方法。

P0不追求把RAG和记忆一次改好，而是建立后续改造的可比较基线，并消除演示与测试中的直接风险。

已确认约束：TXT；《忏悔录》《百年孤独》；API预算充足；用户级稳定偏好+按书阅读目标；明确稳定陈述自动记忆并提示、可疑推断先确认；必要Web支持文件可改；每阶段仍须先确认。

用户另已确认“统一问答入口+自动工具选择+证据约束”的架构方向。执行顺序调整为P0基线→P1a统一问答架构→P1b可核验引用→P2记忆治理→P3个性化优化→P4正式评测；P0仍保留当前普通/Agent双入口，测量后再改，不能把目标架构写成现状或把架构认同视为P0开工许可。

## 2. 本阶段做什么，不做什么

### 做四件事

1. 建立真正隔离的本地测试环境，不让测试写入业务数据库、书籍或旧索引。
2. 去掉密钥相关调试输出，校验记忆类型并修复对应的不安全HTML插值，形成确定性回归用例。
3. 完成20道RAG开发题和10段记忆开发脚本的初测，记录当前问题而不是提前承诺高准确率。
4. 实际跑通现有阅读主流程，整理开题需要的架构、研究问题、实验设计、原型截图和已知限制。

### 本阶段不做

- 不改分块算法、RRF、召回策略，不引入重排或新模型提供商。
- 不在P0合并问答入口或移除Agent开关；这属于P1a，须先保存双入口下的基线与失败案例。
- 不实现引用跳转、语义记忆合并、确认中心或跨书知识检索；这些按后续阶段实施。
- 不把当前低召回、旧偏好误用等已知质量问题当成P0必须修到达标的目标，避免失去基线。
- 不迁移真实密钥、不更换加密算法或ENCRYPTION_KEY。AES-GCM等带完整性保护的迁移另列实施和回滚验收，仍是最终工程底线，不因延后而取消。
- 不更换前端框架、Agent框架、数据库，不做Multi-Agent全书覆盖重构。
- 不修改mobile/、Android分支、Git配置，不提交或推送。

## 3. 拟修改文件与理由

实际实施仍尽量缩小改动；本表是P0确认范围，不是要求每个文件都改。

| 文件/目录 | 计划改动 | 限制 |
| --- | --- | --- |
| `database.js` | 数据库位置允许由测试进程指定独立数据根目录 | 默认业务路径不变；不重建或迁移业务表 |
| `server.js` | 上传/读书目录使用同一数据根；测试可避免加载真实.env；去除密钥片段日志 | 不改问答提示或检索策略，不导出真实密钥 |
| `auth.js` | 默认书与用户书目录跟随测试数据根 | 仅调整路径，不改登录/JWT/注册业务规则 |
| `rag.js` | 旧索引目录也跟随测试数据根，避免测试删除触及真实rag_index | 不改检索算法、分块或排序 |
| `conversation.js` | 对模型返回的记忆kind做枚举校验，拒绝非法类型 | 不提前实现P2的相关性和冲突逻辑 |
| `public/app.js` | 记忆类型仅映射固定样式和安全文本，移除模型字段直接拼HTML路径 | 不重构UI；未知历史kind安全显示，不批量改写已有数据 |
| `package.json` | 添加Node内置测试与显式在线评测命令 | 不安装新依赖；默认测试不得调用付费服务 |
| `tests/` | 添加node:test断言、本地假模型服务、隔离进程与最小人工样本 | 新增文件为测试所必需；不引用业务数据库或密钥文件 |
| `scripts/` | 如测试入口不足以承担交互式基线评测，新增最小评测运行脚本 | 只读指定测试文本；API调用必须显式启动 |
| `docs/` | 测试计划、标注集、统计、脱敏原始记录、报告和开题素材 | 不存真实Key、私人对话或整本受版权保护原文 |

`auth.js`虽然不在最初核心模块清单中，但其 `books` 路径是测试隔离必须统一的Web支持点；只有在本P0方案确认后才调整。`tools/`、`embedding.js`、`text-utils.js`目前不需要为P0修改。

## 4. 执行顺序与实现约束

### A. 先隔离，再启动服务

- 通过进程级数据根参数统一database、server、auth、rag四处路径；不配置时仍用当前业务路径，不编辑用户.env。
- 测试运行器使用操作系统临时目录。运行前检查测试数据根不是仓库根、业务books或rag_index，启动失败即停止，不退回真实数据。
- 离线测试子进程不加载真实.env，不继承供应商Key，使用临时JWT/加密密钥，仅访问本机假模型服务。生产鉴权不关闭、不加认证绕过。
- 注册、上传、建库、删书、删记忆和旧索引清理均限定在临时数据根；优先用人工书籍做破坏性用例。
- 真实测试书只读取或复制到隔离目录，原件不改不删；测试账号和向量索引均在隔离环境创建。
- 使用未占用的本地端口，不终止用户已有服务；测试结束只关闭本轮自己启动的进程，清理本轮创建的临时数据。
- 所有自动化检查必须失败时返回非零退出码；不得静默回退业务路径后继续运行。

### B. 最小安全修正

- 覆盖当前可达的普通/流式问答及密钥校验错误日志，日志不打印Key前缀、Authorization头或可能含密钥的完整上游响应。
- 用人工可识别的测试Key验证服务正常和错误路径均不泄漏；不把测试Key与真实密钥混用。
- 记忆kind接受固定枚举；未知、畸形类型不参与样式/HTML字符串拼接，模型响应仍按不可信输入处理。
- 在浏览器中用人工含HTML的文本验证只显示文字、不会执行内容；不能仅用源代码查找代替UI检查。
- 这些修正不代表全面安全审计，最终报告明确覆盖范围。

### C. 固定测试文本和开发集

已通过目录列举确认：

- `books/__defaults/忏悔录 作者：卢梭.txt`
- `books/__defaults/百年孤独.txt`

P0读取文本时记录：字节数、编码、解码后字符数、文件hash、可识别章节数、长章分布，以及是否为节选。不根据名著名称或模型知识补齐本地文件中不存在的内容。

初始数据集：

| 类型 | 数量 | 组成 |
| --- | --- | --- |
| RAG开发题 | 20题，两本各10题 | 每本各2道事实定位、改述、跨章节、多轮指代、无答案题；若本地为短节选则按实际文本调整并记录 |
| 记忆开发脚本 | 10段 | 明确偏好、同义重复、偏好更正、一次性要求、书籍引用污染、助手推断、无关问题、跨书作用域、删除、新会话回忆 |
| 确定性人工样本 | 按用例所需 | 重复段落、无目录文本、同名不同书、跨用户、非法记忆类型、本地模拟错误 |

人工标注以本地原文范围为金标准，保存必要短引文和定位，不公开整本书。名著可能被模型预训练记住，因此包含无答案题和自编文本对照，不能把“答对名著常识”直接归因于RAG。

### D. 运行基线，不抢跑算法改进

- 主模型和Embedding先使用用户现有可用配置；P0运行准备时通过设置确认具体模型及版本。若隔离环境需要凭据，使用用户在本机配置的测试凭据，不要求在聊天中粘贴、不从真实数据库导出。
- 在线评测与离线测试分开，先展示本轮模型、样本数和用途，再显式运行；预算充足不意味着可以不设任务上限或把文件上传给额外服务。
- 先比较当前BM25和当前混合检索；可由测试运行器构造纯向量参照，不为暴露一个评测接口改动生产检索策略。
- 当前记忆与无长期记忆对照尽量使用同样的会话脚本和模型，测试时新建会话；“关闭记忆”是评测注入条件，不提前增加产品功能开关。
- 有生成随机性的样本建议重复3次；只跑开发集，不用正式保留集调参数。
- 记录样本ID、语料hash、源代码版本/差异摘要、模型、提示和参数、召回片段、答案、实际检索路径、错误/降级、延迟、调用数和token。
- 为后续P1a额外标注“现有选文是否足够、是否需要书内补充证据、是否为长任务”，记录前端入口/Agent开关与实际工具行为；保留旧Agent开启时的基线，不只比较关闭检索的普通模式。
- API usage不可得则明确标记估算或不可得，不编造精确费用。首字时间从请求发起到首个答案内容计时，不把“开始检索”事件算成答案首字。
- 生成可机器读取的JSONL/CSV与人工可读报告；不做一个新后台仪表盘，不改变客户端公共响应仅为了多记指标。

## 5. P0验收标准

### 必须通过的工程关卡

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| P0-01 | 默认与隔离路径 | 默认路径保持不变；自动化测试写操作全部指向临时目录；失败时不回退真实库 |
| P0-02 | 无付费依赖离线运行 | 无真实Key、无外网模型调用时，node:test仍能完成规定回归 |
| P0-03 | 密钥日志 | 人工Key在成功/失败路径不出现在日志、报告或截图，包含前缀泄漏检查 |
| P0-04 | 记忆安全渲染 | 合法kind正常显示；非法kind被拒绝或固定安全降级；人工HTML不会执行 |
| P0-05 | 用户和书籍隔离 | 两个测试账号之间书籍、会话、记忆互不可读写；KNN范围微实验可复现 |
| P0-06 | 开发样本可追溯 | 20道RAG题及10段记忆脚本具有分组、预期、原文/用户证据和评分规则 |
| P0-07 | 在线基线记录 | 固定配置的开发集有原始结果与汇总，成功/失败全部计入；未运行的项目明确标为未测 |
| P0-08 | 浏览器主流程 | 测试账号登录→打开TXT→建索引→划词/普通问答→Agent问答→恢复会话→查看记忆；有步骤记录、截图及控制台/网络检查 |
| P0-09 | 异常与已知缺陷 | 无Key、无索引、Embedding失败和断流场景有记录；新引入回归必须修复，原有缺陷按严重度判断是否阻塞演示 |
| P0-10 | 交付边界 | 分支仍为qoder/web-thesis；没有mobile/改动，没有受保护数据删除，没有密钥进入版本文件 |

P0-09不是承诺当前断流、任务状态等问题已经全部修复。若发现导致主流程无法演示、越权或数据破坏的问题，P0不标完成：先给出最小修复补充范围，由用户确认；低质量回答、无关记忆、采样不足等已知算法/能力问题可作为基线失败样本保留。

### 不作为P0通过门槛的指标

Recall、答案正确率、记忆抽取准确率、偏好遵从率在本阶段只测量，不要求达到P2/P3的目标；不把“不存记忆”“不回答问题”算成质量提升。不以一次顺利演示代替后续正式评测。

离线工程验收与在线基线分别标状态；如果模型尚未配置或网络无法测试，不宣称在线验收完成。

## 6. 开题前的产物与节奏

目标是提供可直接用于开题报告的内容，不在未收到请求时自动制作PPT文件。

| 产物 | 内容 | 开题中能说明什么 |
| --- | --- | --- |
| 问题与目标说明 | 无依据回答、跨会话个性化不足、记忆难纠正 | 选题动机和拟解决的问题 |
| 总体架构与技术路线图 | 阅读产品、RAG证据、记忆治理、Agent调用关系 | 系统设计可行性 |
| 实验设计表 | 两本TXT、合成样本、对照组、指标 | 改进效果可以被验证 |
| 原型截图与短演示流程 | 已有阅读、问答、检索轨迹、会话/记忆页面 | 已有工作基础，区别已实现和计划实现 |
| 初测报告与失败案例 | 如已完成试跑则引用真实数据；否则标明待测 | 对现有不足有证据，而非宣称已实现改进 |
| 分阶段进度安排 | P0→P1a统一问答→P1b引用闭环→P2→P3→P4，2027年具体日期待定 | 工作量可拆解、风险可控制 |

建议开题前先完成P0工程准备和小规模开发集初测，再预留至少1–2天整理材料与演练；是否安排在线演示取决于学校要求和实测稳定性，不强行把尚未验收的新功能塞入答辩。

最适合开题的表述：

> 已实现具备阅读、工具调用、混合检索和基础记忆的Web原型；后续重点研究面向阅读场景的证据可追溯问答与可控个性化记忆，并通过检索、记忆和用户流程对照实验验证工程效果。

不要把“拟实现的来源跳转、冲突纠正、个性化目标”等写成已经完成，也不把方案中的90%质量目标写成实验成绩。

## 7. 阶段完成后的汇报格式

1. 修改文件及每项改动的理由。
2. 确定性测试、在线基线、浏览器验证分别列出通过/失败/未测及原因。
3. 产出的文档、图表、截图和脱敏数据，全部位于docs/。
4. 已知失败样本、需要下一阶段处理的问题与边界。
5. 提交P1a统一问答的具体方案和验收标准，等待确认，不自动开始P1a；P1b引用闭环随后独立确认。

当前只提交本方案。用户明确确认开始P0后，才按上述范围实施。

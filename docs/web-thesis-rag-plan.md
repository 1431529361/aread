# RAG实施方案：定位、引用与检索增量

版本：RAG-1，2026-10-28。状态：待阶段确认的实施设计，未修改业务代码，未执行迁移或在线实验。

前置阅读：[总方案](web-thesis-plan.md)、[共享约定](web-thesis-shared-contracts.md)、[P0方案](web-thesis-p0-plan.md)。本方案覆盖P1b和P3-RAG，不代替P1a统一问答实施方案，不允许跳过P0/P1a直接改公共路由。

## 1. 目标、边界与交付顺序

### P1b必须完成

- 每条新书内证据有真实原文坐标，回答引用可保存、可核验、可点击跳转。
- 规范文本、章节、分块、工具和阅读器使用同一套坐标。
- 索引按版本构建和发布，失败不破坏最后可用版本。
- 保留现有BM25、向量和RRF，真实报告本次降级，不以重写算法作为引用功能的前提。

### P3-RAG才评估

按需多轮查询改写、去重与相邻上下文扩展、可选重排、分块参数调优、缓存容量优化。每次只改变一个因素，取得质量与延迟数据后决定是否保留。

不做跨书知识检索、PDF/EPUB解析、独立向量数据库、知识图谱或全书摘要算法。用户级记忆跨书复用不属于跨书RAG。

### P1a交付前置条件

必须已有：统一ask-stream入口、可信userId/bookId绑定、requestId与消息ID、原始question和selection分离、ToolResult接入点、唯一证据登记/终态/持久化责任、取消和请求预算。缺少前置接口时先报告差异，不能由RAG模块复制另一套问答服务。

## 3. 数据结构与迁移

### 3.1 原则

P1a先建立统一迁移登记；本阶段登记 `web_002_rag_locator`，前置 `web_001_request_contract`。若仓库届时已有不同编号，集成负责人先映射和更新三份文档，不能并行创建两套迁移表。迁移脚本在确认实施时才编写。

保留现有rag_vec的1024维，不把“相同维度”当作“不同模型向量可互相比较”。书内查询还必须限定索引版本与Embedding配置指纹。

### 3.2 表与约束

| 表 | 字段变化/用途 |
| --- | --- |
| rag_chunks | 保留id/user_id/book_id/chunk_index/chapter/text；新增index_version、content_hash、chapter_id、chapter_ordinal、start_offset、end_offset，旧行这些字段可为NULL |
| rag_index_meta | 保留现有列；新增active_version，指向当前已发布版本；现有mode/model/count等列只是当前版本摘要，与active_version在同一事务更新 |
| rag_index_versions（新增） | id TEXT主键、user_id、book_id、content_hash、normalization_version、chunker_version、chunker_config_json、embed_provider、embed_model、embed_fingerprint、dims、distance_metric、mode、status、chunk_count、vector_count、error_code、created_at、finished_at |
| rag_vec | 表结构不变，rowid仍对应rag_chunks.id；写入用BigInt。不能依赖普通外键自动删除虚拟表向量 |

版本status为building/ready/failed/cancelled/retired；mode沿用bm25或embedding+bm25。normalization_version固定txt-v1；distance_metric在首版记录现有l2，不暗中切换余弦或归一化策略。

新增约束：

- 对新块建立 `(user_id, book_id, index_version, chunk_index)` 的条件唯一索引，index_version非NULL时生效。
- 新块要求start_offset/end_offset是合法半开区间；text与原文切片等值由写入校验和测试保证，不能只靠数据库CHECK证明。
- 版本表以 `(user_id, book_id)` 的条件唯一索引限制同书只有一个building版本；所有读取再验证用户和书籍归属。
- 元信息active_version只能指向同用户同书的ready版本；应用事务检查防止错指，不能只按全局UUID查询。
- BM25缓存键改为userId/bookId/indexVersion；容量先保留5，不让新旧块共用缓存。

embed_fingerprint由规范化endpoint、模型名、维度和影响输出的extraBody配置生成哈希，不包含Key。供应商切换、地址变更但model同名也必须判为不兼容；凭据轮换本身不使向量失效。

### 3.3 旧数据迁移

1. 在隔离库执行，加列、建新表与索引，记录迁移版本；重复执行不得重复建数据。
2. 旧块和旧向量不删除；旧meta的active_version=NULL，UI标记“旧版索引，需要重建定位”。不通过text.indexOf反推位置，重复段落会导致错误。
3. 新版引用链不消费没有locator的旧块。用户确认单书重建后发布新的版本；重建前可使用规范章节/全文工具取证，不能假装旧引用已经可跳转。
4. 旧聊天原样保留，metadata为空时显示旧版记录，不给已有答案伪造来源。
5. 迁移本身不联网向量化，不删除rag_index目录，不改书籍原件、密钥或历史消息。

### 3.4 备份与回滚

- 真实库迁移另行确认，先停止本应用的写任务或使用SQLite原生backup得到一致副本；不能只复制活跃WAL数据库的data.db文件。
- 备份放用户确认的非提交位置，包含隐私数据，不上传、不纳入Git。
- 迁移失败回滚本次事务；新版应用启动失败应停止而非在错误schema上继续服务。
- 真正还原旧库需停写并确认还原点之后的数据处置，不自动覆盖新的用户记录。新版索引失败优先回切active_version，不借机回滚整库。

## 4. 规范文本、章节与分块

### 4.1 唯一规范文本

遵守共享约定：解码→去开头BOM→CRLF/CR改LF；不trim、不合并空行、不做Unicode归一化。`contentHash = txt-v1:SHA256(UTF8(content))`。文件原始字节hash单独用于实验资产清单，不作为locator hash。

在text-utils定义语义接口：`normalizeText(decodedText)`、`parseChapters(content)`、`sliceAtSafeBoundary(content,start,end)`。函数命名可在实施前统一，但输出语义不得改变。

### 4.2 章节解析

- 扫描原始行并保留每行start/end；仅使用行的trim副本判断标题，原文范围不裁剪。
- 复用现有中文“第…章/节/回”等及英文Chapter规则，暂不添加LLM章节识别。
- 标题行开始到下个标题行之前构成章节；前导非空内容作为“前言”，没有标题时构成“全文”。合成名称只是结构标签，不当作原文标题。
- 章节DTO固定 `{ id, ordinal, title, start, end }`。id采用 `ch-<ordinal>-<start>`，同文本/同解析版本可复现，重复标题靠ordinal/start区分；章节范围覆盖对应规范文本。
- 只含空白的文档拒绝建索引，不能生成一个空“全文”假成功。

### 4.3 P1b分块算法

先保留当前规模参数作为起点：目标500码元、长段二次切分触发750、滑窗重叠100；这不是已经证明最优的参数。

1. 在章节范围内按段落边界累计连续原文区间，达到目标大小时刷新。
2. 刷新区间不超过750时保留整个连续范围；超过750时按500长、约100重叠生成范围。当前500并非所有块的硬上限，文档与UI不要写错。
3. 切分边界避开UTF-16代理对；必要时移动1码元，保证每次向前推进，杜绝死循环。
4. 每个块text严格取规范原文slice，内部空行/缩进保留；不把章节标题复制到每个块正文。
5. 普通相邻累计块先不额外加重叠，与长段滑窗情况分别记录；新范围算法引起的边界变化作为基线差异报告。
6. 所有非空白原文码元至少被一个块覆盖；块不能跨章节，末尾短块不丢弃。

chunker_version与配置入版本表。P3调整参数生成新版本，不悄悄覆盖已有元信息或沿用不匹配的向量。

## 5. 索引构建、并发与状态

### 5.1 构建流程

1. 校验用户/书籍/格式，读取规范文本及hash，固定本次Embedding配置与分块参数。
2. 短事务创建building版本；同书已building返回409 INDEX_BUILD_RUNNING，其他书不互相阻塞。
3. 分块写入新index_version，不先删active版本；产生块数量和总量进度。
4. 如可向量化，分批调用现有提供商，默认每批10、构建并发1。每批返回后在同一个写入短事务内重新检查版本仍building、构建令牌未作废、书仍属于用户、对应块全部存在且属于本版本；任一不满足就丢弃整批，不得向rag_vec插入孤儿rowid。
5. 每个向量必须维度正确、元素有限、与输入顺序一致；响应有index时按index重排并检查重复/缺失。无index的提供商必须在适配器明确保序，不能猜测。
6. 发布前复核规范文本hash及块/向量计数和locator；进入发布短事务后再次验证书籍归属与构建令牌，用条件更新确认仍building。检查不通过时不切换指针。
7. 同一发布事务将新版本标ready并原子切换active_version及摘要字段；不得在一次检查与发布之间等待网络。读请求看到的应是完整旧版本或完整新版本。
8. 清理仅限派生索引行，遵循第5.3节；不删除或移动用户书籍和旧rag_index目录。

### 5.2 失败与降级

- 本来未配置Embedding/扩展不可用：完整BM25版本可发布，明确mode=bm25。
- 配置了Embedding但本次失败：若已有有效active版本，保留它，新构建标failed；不要用失败的重建静默替换旧混合索引。用户可另选仅BM25重建。
- 首次建库没有有效active版本且Embedding失败：若块完整，可发布BM25版本并返回明确警告；失败向量清理不得影响其他版本。
- 用户取消、书删除、内容变更或部分块写入失败：不发布，标cancelled/failed；保留旧active，释放构建锁。
- 进程重启遗留building：标failed（中断），不自动重放付费任务；可由用户重新构建。
- 全库或全书删除操作必须先终止/作废该书构建令牌，阻止迟到批次发布，删除派生向量时按同用户同书版本约束。

### 5.3 查询快照和清理

查询取得active版本后固定其ID与配置，并登记本进程的使用计数，finally释放。网络等待期间不持有数据库事务。发布后旧版本有在途读请求时不得清理；取消/时限限制防止永久占用。

新体系通常保留当前与前一个成功版本；其他由新体系产生的版本在使用计数归零后清理。旧迁移数据不在首次升级时自动清理；其派生行清理要在单书重建说明中明确并确认。rag_vec需先删对应rowid，再删块/版本，不能只删普通表留下孤儿向量。

v1只承诺单进程部署；多进程需要跨进程读版本租约，不在本阶段偷偷加Redis。若实施选择其他快照方法，必须证明同等不混版语义并更新本节。

### 5.4 索引API视图

保留现有建库/状态路径，新增字段统一如下：

```text
IndexStatus = {
  usable: boolean,
  active: null | { indexVersion, contentHash, mode, chunkCount, vectorCount },
  build: null | { indexVersion, state, processedChunks, totalChunks, error },
  rebuildRequired: boolean
}
```

GET `/api/books/:id/index-status`返回此视图；POST `/api/books/:id/index`构建结束返回同一视图及warnings；v1继续有界HTTP构建，不增任务队列，客户端可查询状态了解正在进行的构建。断开构建请求时传播取消，不能留下无主任务。

`usable`要求active就绪且内容hash与当前规范文本匹配；build失败与active可用可以同时成立。旧版索引rebuildRequired=true，不把“数据库有旧行”显示成新版可用。

## 6. 检索流水线与工具集成

### 6.1 P1b基础检索

1. 问答服务已决定是否取证；rag只处理明确的书内检索请求，不再次独立调用意图分类模型。
2. 传入共享约定的userId/bookId/query/topK/signal/deadlineAt/expectedContentHash，定位当前可用版本并匹配请求文本hash；不同版本返回INDEX_STALE，不拼接旧书证据。
3. 立即执行本地BM25，同时启动可用的查询向量请求；不先等网络失败再开始本地检索。BM25同步CPU工作不宣称真正并行CPU计算。
4. 默认两路各取10，再RRF(k=60)，最终5；在同版本块ID上融合去重，保留原评分类型和排名。
5. 向量KNN限定user+book+index_version对应的rowid集合；固定当前扩展已有的范围过滤方案，测试先行，不凭SQL书写顺序推断有全局过滤缺陷。
6. 获取每条候选的真实text、chapter、locator，按SC的EvidenceCandidate返回；记录indexVersion与本次路径。
7. 分数代表排名，不等于答案正确概率。rag返回ok表示得到候选，不代表它们一定能支持结论；问答服务仍执行证据门控。

默认查询向量分支软预算建议8秒、无自动查询重试，取min(该预算,请求剩余时间)；值在开发集上调整并冻结。分支超时可使用已得到的BM25并记录VECTOR_TIMEOUT；整个请求取消或deadline到期必须终止，不得当成普通降级继续生成。

### 6.2 错误矩阵

| 情况 | 检索结果 | 上层行为 |
| --- | --- | --- |
| 两路可用且有候选 | ok，实际路径均成功 | 正常取证 |
| 向量分支失败，BM25有命中 | ok+warning，只标本次真实路径 | 继续回答，不伪称hybrid |
| 两路成功但无可用候选 | empty | 补查/澄清/缺证 |
| 无索引或只有旧版定位索引 | unavailable，INDEX_UNAVAILABLE/INDEX_LEGACY | 允许规范章节或全文工具；不暗中全书建库 |
| 请求hash与索引不同 | unavailable，INDEX_STALE | 提示更新索引或读取当前规范章节，不能引用旧版本 |
| 两路均失败且无结果 | error | 明确失败；不能伪装成书里没有答案 |
| 用户取消/总时限 | 抛可识别终止异常 | 结束请求，不继续召回或重试 |

全文子串兜底只对有意义的非空查询使用，按规范文本返回实际位置；重复命中可返回多处但有上限，不能永远选第一次冒充唯一出处。不可用与空命中原因不混同。

### 6.3 三类工具

- searchInBook：透传候选，不再只映射chapter/score/text。diagnostics保留indexVersion。
- getChapterInfo：使用服务端chapter.id或ordinal，若标题匹配多章返回歧义信息，不任取第一章；长章截取必须有truncated与真实locator，不把预览叫作摘要。
- lookupCharacter：返回规范文本中的多处片段；换行不先替换为空格；returnedOccurrences仅表示本次返回数，不代表全书总次数。

工具返回ToolResult；问答服务负责E1登记、模型上下文预算与引用白名单。非连续证据不要拼成一条伪造连续locator。

## 7. 引用持久化与前端跳转

### 7.1 后端证据流程

候选校验→按内容版本和区间去重→按模型预算选取→分配本轮E编号→送入模型→最终引用校验→与助手消息metadata原子保存。

只有实际送入最终回答上下文的片段能成为引用白名单。后续裁剪如果移除了证据，必须同时从最终白名单移除；不能只保留UI显示的ID。answer_start后冻结集合。

保留 `[[E1]]` 标记。无效ID或不完整标记不能生成可点击链接；服务端规范化为“引用无效”并记录warning，使最终正文、历史正文与实时展示一致。无需追求用程序证明语义支撑；由固定标注集单独评价。

### 7.2 阅读器数据与选文

P1b的GET书籍返回规范content、contentHash与chapters。每个渲染块保留start/end，块内文本以createTextNode创建，保留换行和空白；章节标题用服务端章节标识。排版使用CSS，不用trim后的HTML反推原文位置。

建立Text节点到规范文本偏移的映射，选区起止通过映射计算；selection.text用规范content.slice(start,end)，不要依赖Range.toString可能加入的布局换行。若跨出阅读正文或无法映射，不发伪造locator，降为用户给定文本或要求重新选择。

### 7.3 跳转过程

1. 点击当前消息的合法引用按钮，根据该消息requestId+evidenceId获取快照。
2. 校验bookId权限并加载/校验当前规范contentHash；不同版本提示“原文已变化，无法准确定位”。
3. 根据start/end找到相交渲染块，将原文分成before/highlight/after文本节点，仅改相交块；各新节点重建偏移映射。
4. 滚动到首个高亮块；支持返回原对话并保留当前会话和滚动位置。
5. 再次跳转先按规范文本恢复上次高亮块，不通过innerHTML替换或全书字符串搜索定位。

要求覆盖跨段落、重复文字、章节标题、空行、中文及代理对场景；字体/主题变化不影响偏移。服务端已有章节信息与全书文本即可完成，不引入第三方阅读器。

书已删除/权限丢失：显示来源不可用；索引重建但内容hash相同：仍可跳转，不要求旧chunkId存在。证据快照留在消息metadata，不再发检索请求寻找“类似原文”。

## 8. P3-RAG增量设计

| 增量 | 实现边界 | 纳入条件 |
| --- | --- | --- |
| 多轮改写 | 仅指代不明/省略实体时，把当前问题与少量最近已完成对话送入现有模型，返回独立检索问题；保留原问题，不改变用户诉求 | 开发集指代题召回改善且总延迟可接受 |
| 相邻/父范围扩展 | 子块召回后在同章节原文区间扩展到相邻段落，合并重叠区间；初始上限1500码元/证据，整体仍受Token预算限制 | 多证据题支撑率改善，不被更长片段掩盖检索变差 |
| 重排 | 对融合候选有限重排，优先复用已有可用提供商；新增配置/服务必须另行确认；失败保留原排序并记warning | MRR/支撑率收益超过额外时延与调用成本 |
| 分块参数 | 例如目标400/800/1200，重叠与目标成比例；每种新索引版本记录同样配置 | 只在开发集选择，保留集不调参 |
| 缓存 | 测5本缓存下冷/热耗时和内存后调整上限或预热 | 确实存在可测瓶颈，不预先换FTS5 |

改写失败使用原问题，不发散成跨书搜索；模型返回的改写文本同样不可信，要限定长度并禁止篡改bookId。P3的检索参数进入配置和实验版本，不增加面向读者的技术模式开关。

## 9. 实施拆分与验收

P1b内部按R1→R2→R3→R4执行；单一阶段已确认后可顺序完成这些子任务，不将每一行都变成额外确认弹窗。重大范围变化仍先确认。

| 子任务 | 产出 | 完成标准 |
| --- | --- | --- |
| R1 文本与迁移 | 规范化/章节/范围分块纯函数、迁移与索引版本表 | 确定性文本测试和旧库副本迁移通过；不联网、不写原件 |
| R2 构建与检索 | 版本构建/发布、缓存、召回诊断、三个工具来源 | 同书互斥、失败保旧、取消、模型指纹、隔离与不混版测试通过 |
| R3 引用前后端 | E编号、metadata、坐标映射、跳转 | 浏览器主路径及至少20个定位/引用场景通过，历史可恢复 |
| R4 评测与交接 | P0对照、结果报告、图表/截图 | 固定开发集有实际结果，失败样本未删，公共契约无未说明变更 |

P3-RAG作为独立确认的后续任务，每项增量保留禁用该增量的测试条件用于消融，不把这些测试条件做成普通用户必须选择的开关。

### 9.1 确定性测试用例

| ID | 输入/故障 | 预期 |
| --- | --- | --- |
| R-T01 | BOM、CRLF、单CR、空行混合 | 规范化确定，等价换行输入hash一致，内部空格不丢 |
| R-T02 | 重复段落/重复章节名 | 不同出现位置有不同locator，跳到被引用的那一处 |
| R-T03 | 长章、超长单段、末尾短段 | 非空白覆盖完整，范围合法，无跨章、漏尾或死循环 |
| R-T04 | `A\uD83D\uDE00B` 位于分块边界 | 不切断代理对，slice与候选text完全相同 |
| R-T05 | 全空白TXT | 拒绝建空索引，UI说明原因 |
| R-T06 | 同用户不同书+不同用户更近向量 | 只召回目标user/book/version，不发生全局污染 |
| R-T07 | Embedding第2条维度错/NaN/重复index | 拒绝该批，不能部分发布混合版本 |
| R-T08 | 同书双重建 | 只有一个building，另一个409，旧active仍能查 |
| R-T09 | 重建中断/取消/进程重启 | 未发布版本不可见，旧active不丢，重启不自动付费续跑 |
| R-T10 | 发布新版本时旧查询等待向量API | 查询只用自己固定版本，旧版未在查询完成前清理 |
| R-T11 | 删书/取消后才返回向量批次；发布前改变正文 | 迟到批次既不能写rag_vec孤儿行，也不能发布；条件更新失败不切指针 |
| R-T12 | Endpoint改变但模型名相同 | 不使用不兼容查询向量，BM25降级有原因 |
| R-T13 | 向量超时、BM25命中 | 在分支预算内降级，标实际BM25；用户取消则终止 |
| R-T14 | 无命中与两路均失败 | 分别empty和error，不混报“书里没有” |
| R-T15 | JSON大结果、截短章节 | 可解析且truncated=true，截短后的坐标与text一致 |
| R-T16 | E编号跨SSE块、未知E99、未闭合标记 | 只让合法完整标记可点击，最终保存/历史显示一致 |
| R-T17 | 重开会话、索引重建但原文未变 | 快照可恢复且仍能定位，无须再次检索 |
| R-T18 | 内容hash改变、无权限、书已删除 | 显示失效/不可用，不错跳，不泄露原书 |
| R-T19 | 改字体/主题、跨段落高亮后再次选文 | offset不变，选文仍能被服务端验证 |
| R-T20 | 新旧索引清理 | 只删除对应派生版本，rag_vec无新增孤儿，原件/旧目录不动 |

所有数据安全/权限/坐标/发布状态不变量要求100%通过；当前模型回答质量不在纯函数测试里假装验证。

### 9.2 质量评测与论文材料

- 两本指定TXT，以实际本地版本为准；P0开发集20题先用于验证，最终约60题分开发/保留集，按章节/问题族隔离。
- 依次报告旧BM25/旧混合、P1b坐标化后的BM25/混合、P3单项增量；记录规范化与边界变化，不把引用能力提升归因为更高语义召回。
- 指标：Hit@5、Evidence Recall@5、MRR@5、答案正确率、引用合法率、引用支撑率、缺证处理率、检索/首字/总耗时、调用数与费用。
- P1b不承诺虚构的召回提升百分比；引用合法/坐标正确目标100%，语义指标如实报告。P3仅保留在冻结标准下有效的增量。
- 素材：规范文本/原文定位图、索引发布状态图、RAG流水线、版本表ER图、引用跳转截图、失败保旧截图、冷/热延迟表与消融表。

## 10. 交接和停止条件

执行者必须提交文件清单、迁移版本、测试命令及退出码、浏览器步骤/控制台结果、真实模型配置名称与参数、未测项；不能只说“代码已写完”。文档和脱敏结果放docs/。

如P1a还未提供公共接口、sqlite-vec行为与测试不符、真实数据需要迁移但未获批准、需新增模型服务、或公共类型需改变，停止对应步骤并说明，不使用删库/忽略失败/伪造locator作为捷径。

# M0-B 真机验收清单

M0-B 的代码与离线测试已完成，但当前开发环境没有 Android 设备/模拟器，以下设备侧结果必须按清单在真机上确认。验收目标以 `android-app-spec.md` 为准：**飞行模式可读书；重启 App 后书架、会话、进度都在**。

## 0. 构建与安装

- [ ] Android 8.0+（API 26）真机，开启开发者选项与 USB 调试，`adb devices` 能看到设备
- [ ] `cd mobile && npx expo run:android --device` 完成 dev build 编译并安装
- [ ] 冷启动进入 onboarding（首次安装）；授予通知/文件访问等无阻塞弹窗
- [ ] 不要用 Expo Go（op-sqlite、SecureStore 需要原生模块）

## 1. 启动与能力诊断

- [ ] 完成 onboarding 后进入「设置」，确认诊断卡：
  - FTS5：可用，或明确显示“已降级”
  - 流式：`expo-fetch`（若显示 `xhr-sse`，记录设备/系统信息）
  - Schema：7
  - 书籍/分块/会话/划线数量随操作增长
- [ ] 若 FTS5 不可用：导入后仍能在搜索页命中，且设置页有降级提示（`rag_lexical` + JS BM25 路径）
- [ ] 点击“重新检测”不崩溃，状态可刷新

## 2. 模型配置

- [ ] 对话模型：Base URL（OpenAI 兼容，如 `https://api.example.com/v1`）、Model、API Key 填写后“测试连接”成功
- [ ] 只填聊天、不填向量也能完成 onboarding（M0-B 仅需词法检索）
- [ ] 向量模型：填写后测试必须返回 1024 维；维度不符会被拦截，且无法保存
- [ ] 杀掉 App 重开，设置里显示的是密钥掩码，原文不再出现；数据库中无明文 Key
- [ ] 错误 Key / 断网时测试连接给出可读错误，不白屏

## 3. TXT 导入

准备以下文件（桌面端可生成）：

```bash
printf '第一章 开始\n这是 UTF-8 正文。\n\n第二章 继续\n换行与空行都应保留。\n' > /tmp/utf8.txt
printf '\xff\xfe' > /tmp/utf16le.txt
printf '第一章\r\nUTF-16LE 正文\r\n' | iconv -f UTF-8 -t UTF-16LE >> /tmp/utf16le.txt
printf '中文内容' | iconv -f UTF-8 -t GBK > /tmp/gbk.txt
head -c 52428801 /dev/zero | tr '\0' 'a' > /tmp/too-large.txt
```

- [ ] UTF-8：导入成功，书名取文件名，书架出现书卡，状态变为“可检索”
- [ ] 带 BOM 的 UTF-8、带 BOM 的 UTF-16LE/BE：正文无乱码
- [ ] GBK：明确提示“仅支持 UTF-8/UTF-16，GBK 将在 M1 支持”，书架不新增乱码书
- [ ] 超过 50MB：被拒绝并提示拆分
- [ ] 同一文件重复导入：提示已存在，不产生第二本
- [ ] 导入过程中进度弹窗有阶段文案；完成后可立即阅读
- [ ] 取消文件选择：不报错、不新增记录

## 4. 阅读与离线

- [ ] 打开书进入阅读器：正文分段正确，首段不丢字，长段落不溢出屏幕
- [ ] 目录：章节列表可打开，点击任意章节跳转且定位准确
- [ ] 字号 14–30、行高 1.4–2.2、纸张/护眼/夜间主题切换即时生效
- [ ] 上下滚动后退出再进入：回到上次位置（不是顶部）
- [ ] 打开飞行模式（关闭 Wi-Fi + 移动数据），杀掉 App 重开：仍能打开书、翻页、调样式
- [ ] 飞行模式下发起提问：给出“未配置/网络不可用”的明确提示，不崩溃

## 5. 划词、划线、搜索

- [ ] 长按选择一段文字：底部出现“提问/划线/全书搜索/复制/取消”
- [ ] 点“提问”：进入该书会话，输入框上方显示引用文本；发送后回答针对选区
- [ ] 点“划线”：选区高亮；退出重进仍保留；再次划线可切换颜色
- [ ] 点“全书搜索”：带入选中词，结果显示片段与命中数
- [ ] 搜索页手动输入关键词：中文、英文、特殊字符（引号 `-"*`）都不报错
- [ ] 点击搜索结果：跳回阅读器对应段落并有闪烁提示
- [ ] 划线管理：书籍详情页可看到划线并删除，删除后阅读器高亮同步消失

## 6. 会话与引用

- [ ] 首次提问自动创建“本书会话”；再次提问复用同一会话
- [ ] 回答逐字流式输出；中途点“停止”保留已生成内容
- [ ] 回答中的 `[C1]` 等标记可点击，跳到引用原文
- [ ] 引用卡片显示章节/片段，点击可跳转
- [ ] 会话历史在重启后仍在，引用快照可点开
- [ ] 书籍详情页“新建会话”后，旧会话归档，新会话从空开始
- [ ] 断网/401/超时：消息不丢失，可重试，错误提示可读

## 7. 重启持久化总检

依次确认以下内容在**杀掉进程并重开**后仍存在：

- [ ] 书架：书籍、顺序（最近阅读优先）、进度百分比
- [ ] 阅读器：上次 locator 与滚动位置
- [ ] 会话：标题、消息、引用、当前 active 会话
- [ ] 划线：文本、颜色、位置
- [ ] 设置：主题/字号/行高、Provider 配置（Key 掩码）
- [ ] 诊断：schema=7、FTS5 状态、数量统计

## 8. 删除与清理

- [ ] 书籍详情删除书：二次确认后返回书架，书消失
- [ ] 删除后 `books/<id>.txt`、chunks、会话、消息、划线、任务缓存均清理（可在诊断数量中确认）
- [ ] 卸载重装：本地数据清空，onboarding 重新出现（M0-B 不做备份恢复，M3 验收）

## 9. 已知限制（不作为 M0-B 阻塞项）

- 整本 TXT 一次性生成 WebView HTML，未做虚拟列表；接近 50MB 的书可能打开慢或占用较高内存。建议 M1 前改为分章/分段懒加载。
- GBK/GB18030 明确拒绝，M1 通过 iconv 支持。
- M0-B 不做向量索引与跨书会话；检索为单书词法检索。向量/混合检索在 M2 验收。
- FTS5 降级路径排序与 FTS5 的 `bm25()` 不完全一致，但满足“能搜到、可跳转”。
- `expo/fetch` 流式失败时仅在“尚未收到任何增量”时切 XHR SSE，避免重复输出；若首个 chunk 后失败，会直接报错而不是重放。

## 2. 采纳决策

| 增量 | 决策 | 依据 |
| --- | --- | --- |
| 分块参数 | **采纳 1200/1800/240 为默认**（`text-utils.DEFAULT_CHUNKER_CONFIG`，版本表记录 chunker_config） | 相对500在 Hit/Recall/MRR 全面改善且延迟不变；多次运行方向一致；回收 P1b 边界回落 |
| 邻接/父范围扩展 | 实现但**不设为默认**（`retrieveDetailed opts.expandAdjacent` 保留为消融/可选） | 仅在小分块(500)有益；在采纳的1200上 Hit/Recall 不变、MRR 仅+0.01 且+10ms，无一致收益 |
| 重排 | 保持**可选、默认关闭** | MRR 提升但延迟约2.9倍（334 vs 116ms）且 Recall 低于1200；不满足冻结延迟/覆盖预算 |
| 多轮改写 | 实现并评估后**不采纳**（已从产品补查路径移除；消融脚本保留可复现） | 在采纳1200分块下 coref 召回反而下降（1.0→0.5）；不满足“指代题召回改善”纳入条件 |
| 缓存容量 | **不改动**（LRU max 5） | 冷/热几乎无差（122/119ms），无可测瓶颈；不换 FTS5 |

## 3. 实现与测试

- `rag.js expandAdjacentRanges`：同章节段落边界扩展、合并重叠（仅同章）、上限1500码元、真实连续 locator；单元测试（rag-retrieval.test.js「P3 邻接扩展」）验证不跨章/上限/slice 一致。
- `text-utils.js`：DEFAULT 改 1200/1800/240，保留 `P1B_CHUNKER_CONFIG`(500) 供边界类测试钉住；新增默认配置断言测试。
- `scripts/run-p3-ablation.js`：单因素消融（分块/扩展/重排/改写/缓存），每项保留禁用条件；改写用真实模型（maxTokens 需≥400，思考型模型100会返回空）。
- 离线 `npm test` 76/76 通过。

## 4. 口径与限制

- 开发集选择阈值，保留集不调参；本报告为开发集初测。
- 检索存在运行间波动（n=16，±1题≈0.0625）；决策依据多次运行的**一致方向**而非单次数值。
- 端到端（Agent 多轮检索）Hit@5 在 P1b 评测已达0.875；直连检索消融用于归因单个增量，二者口径不同。
- 改写/扩展未采纳不代表实现删除：扩展保留为可选参数，改写逻辑保留在消融脚本中供复现与后续重评。
